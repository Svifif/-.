# Лабораторные работы по курсу «Теория многоагентных систем»

Многоагентная система **DiSMA** (Distributed Scheduling Multi-Agent system) —
распределение вычислительных заданий в гетерогенном кластере.
Все четыре лабораторные работы выполнены на одной системе: ЛР1 — проект,
ЛР2 — механизмы распределения, ЛР3 — переговоры при дефиците GPU-ресурса,
ЛР4 — диверсионный анализ и защита.

## Структура

```
mas/                 общий движок МАС (используется всеми работами)
  config.py          титульные данные отчётов и стоимостные константы
  model.py           агенты, сообщения, симулятор, метрики, генераторы нагрузки
  mechanisms.py      централизованная диспетчеризация, контрактная сеть, аукцион
  negotiation.py     торг, приоритезация, арбитраж, санкции, квоты (ЛР3)
  malice.py          сценарии атак и защитные механизмы (ЛР4)
  report.py          сборка отчётов .docx (python-docx)
lab1/main.py         ЛР1: диаграмма ролей, граф коммуникаций, отчёт
lab2/main.py         ЛР2: эксперимент по трём механизмам, отчёт
lab3/main.py         ЛР3: эксперимент по трём режимам переговоров, отчёт
lab4/main.py         ЛР4: 7 сценариев атак × 2 режима, отчёт
demo.py              консольная демонстрация работы системы в разных режимах
```

Отчёты и рисунки складываются в `labN/out/`:

* `lab1/out/ЛР1_отчет.docx` — спецификация и архитектурное проектирование;
* `lab2/out/ЛР2_отчет.docx` — исследование механизмов распределения;
* `lab3/out/ЛР3_отчет.docx` — переговоры и разрешение конфликтов;
* `lab4/out/ЛР4_отчет.docx` — диверсионный анализ и надёжность.

## Запуск

```powershell
python -m pip install python-docx matplotlib
python lab1/main.py
python lab2/main.py
python lab3/main.py
python lab4/main.py
```

Каждый скрипт сам считает эксперимент, строит рисунки и собирает отчёт,
поэтому отчёты всегда согласованы с кодом. Полный прогон занимает около
минуты.

Демонстрация работы системы (требование о работе «в разных режимах»):

```powershell
python demo.py list
python demo.py run --mode auction --profile heavy --jobs 60 --trace
python demo.py negotiate --mode full --trace
python demo.py attack --id S4 --defense
```

## Модель в двух словах

Кластер: 3 CPU-узла (node-a, node-b, node-legacy) и GPU-узел, суммарная
мощность 18,6 усл. ед./тик. Заказчики подают заявки с объёмом, директивным
сроком, приоритетом и предельной ценой. Брокер распределяет заявки, исполнители
автономно назначают цену и принимают обязательства, арбитр разрешает конфликты,
монитор контролирует достоверность. Время — целочисленные тики, все сообщения
проходят через одну шину и считаются (стоимость координации).

Основные метрики: доля нарушений SLA, среднее время отклика, makespan,
число сообщений на задание, стоимость координации и выполнения, коэффициент
Джини по загрузке узлов, индекс Джайна и отклонение от квот.
